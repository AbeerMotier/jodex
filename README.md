# جُودِكس — نظام تقييم ومتابعة نظافة دورات المياه

نظام متكامل يعمل فعليًا بحسابات وبيانات حقيقية: المستفيد يقيّم عبر رمز QR دون حساب، ومراقب المقاول (الأساسي أو النائب)
ينفّذ جولتين يوميًا بصور حقيقية، ومشرف الوزارة يقيّم المواقع المسندة إليه، والأدمن يتابع كل ذلك عبر لوحة تحكم
(مؤشرات، سجل، تقييمات، ملاحظات، أداء ومكافآت، رموز QR، أوزان وإعدادات) مع تصدير PDF/Excel.
الواجهة عربية بالكامل (RTL) بخط IBM Plex Sans Arabic، والمرجع الزمني الوحيد وقت الخادم بتوقيت `Asia/Riyadh`.

| الطبقة | التقنية |
|--------|---------|
| الواجهة والخادم | Next.js 16 (App Router) + TypeScript + Tailwind CSS 4 |
| الخلفية الوحيدة | **Supabase**: Postgres (RLS + دوال ذرّية + pg_cron) · Auth · Storage خاص |
| التحقق | Zod على العميل والخادم |
| QR / Excel / PDF | `qrcode` · `exceljs` · Playwright (HTML → PDF) |
| الصور | فحص البصمة الثنائية، HEIC→JPEG، إزالة EXIF/GPS (`sharp`)، روابط موقّعة 300 ثانية |
| الاختبارات | Vitest (وحدات + تكامل قاعدة البيانات) · Playwright (تكامل شامل عبر المتصفح والواجهات البرمجية) |

## فتح المشروع في Visual Studio Code

1. من شاشة البداية في VS Code اختر **Clone Git Repository** والصق `https://github.com/AbeerMotier/jodex.git`
   (أو من الطرفية: `git clone https://github.com/AbeerMotier/jodex.git` ثم `code jodex`).
2. وافق على تثبيت **الإضافات المقترحة** (ESLint، Tailwind CSS، Playwright، Vitest).
3. افتح الطرفية المدمجة (`` Ctrl+` ``) ونفّذ خطوات «التشغيل محليًا» أدناه. بعد إعداد `.env.local` يمكنك التشغيل من
   **Run and Debug** ← «جُودِكس: تشغيل التطوير»، وكل أوامر npm ظاهرة في لوحة **NPM SCRIPTS**.

## التشغيل محليًا

**المتطلبات:** Git، و Node.js ‏22 أو أحدث، و Docker Desktop (شغّال). أداة Supabase CLI تُثبَّت تلقائيًا مع `npm ci`
(مثبتة كإصدار محدد في `devDependencies`) وتُستدعى بـ `npx supabase`.

```bash
npm ci
npx playwright install chromium   # متصفح لتوليد تقارير PDF ولاختبارات Playwright

# 1) Supabase المحلي (Postgres + Auth + Storage) — يطبّق الترحيلات في supabase/migrations تلقائيًا
npx supabase start

# 2) ملف .env.local تلقائيًا (عنوان Supabase ومفاتيحه + أسرار عشوائية) — لا يستبدل قيمًا موجودة
npm run setup:env

# 3) البيانات الأساسية (idempotent) — تُطبع كلمات مرور الحسابات الجديدة مرة واحدة فقط، احفظها فورًا
npm run db:seed

# 4) التطبيق
npm run dev                     # http://localhost:3000/login
```

- لإعادة ضبط قاعدة البيانات المحلية بالكامل: `npm run db:reset` ثم `npm run db:seed`.
- لتجربة مسح رموز QR بجوال حقيقي على نفس الشبكة: اضبط `PUBLIC_APP_URL=http://<IP-جهازك>:3000` في `.env.local`
  وشغّل `npm run dev -- -H 0.0.0.0` (رموز QR تحمل هذا العنوان).
- `DEMO_MODE=true` يعرض قائمة الحسابات التجريبية (أسماء المستخدمين فقط) في صفحة الدخول للعرض المحلي — **ممنوع في الإنتاج**.
- لا توجد كلمات مرور ثابتة إطلاقًا: كل كلمة مرور عشوائية (16 حرفًا) وتُطبع مرة واحدة عند الإنشاء.

| الأمر | الوظيفة |
|-------|---------|
| `npm run dev` / `build` / `start` | التطوير / البناء / التشغيل |
| `npm run lint` · `npm run typecheck` | الفحص الثابت |

## المهام المجدولة

مُعرّفة في `supabase/migrations/20261015000500_cron.sql` عبر **pg_cron** (الأوقات بتوقيت UTC):

| المهمة | بتوقيت الرياض |
|--------|----------------|
| إنشاء جولتي اليوم لكل دورة مياه لها مراقب أساسي نشط | 00:01 |
| إغلاق الصباحية غير المرسلة كـ«فائتة» (درجة 0) | 11:01 |
| إغلاق المسائية غير المرسلة | 16:01 |
| إغلاق متأخر + تنظيف سجلات تحديد المعدل | 00:05 |

احتياطًا، يُنفّذ الخادم نفس الخطوتين (إنشاء ثم إغلاق) قبل كل قراءة أو إرسال، فلا تتأثر القواعد إن تأخرت المهام.
بديل اختياري لمجدول خارجي: `POST /api/cron/tick` مع `Authorization: Bearer $CRON_SECRET`، أو `npm run cron:tick`.

## الاختبارات

```bash
npm run test:unit          # قواعد العمل النقية (الالتزام، الجودة، المشرف، المؤشرات، التحقق)
npm run test:integration   # على Supabase المحلي: seed مرتين، RLS لكل دور، الدوال الذرّية، القفل، نافذة المستفيد
npm run test:e2e           # يبني التطبيق ويشغّله على المنفذ 3100 ويختبر عبر المتصفح والواجهات البرمجية
```

- اختبارات التكامل وPlaywright تنشئ «عالم اختبار» معزولًا لكل تشغيل (مبنى ودورات مياه وحسابات بأسماء فريدة
  وكلمات مرور عشوائية في الذاكرة فقط) وتعطّله في النهاية، وتستعيد الأوزان والإعدادات.
- تعتمد على **ساعة اختبار** (`JODEX_ALLOW_TEST_CLOCK` + سر عشوائي لكل تشغيل) لتثبيت «وقت الخادم» على تواريخ مستقبلية بعيدة،
  لذا **تُشغَّل على Supabase المحلي فقط** (ترفض أي عنوان غير محلي). يُفضّل `npm run db:reset && npm run db:seed` قبلها وبعدها.
- تغطي متطلبات القسم 11: القيم الحدية للالتزام بدقة الدقيقة، حالات الجولة، رفض الناقص وإلزامية التنظيف العميق في يومه،
  النائب (executed_by/on_behalf_of)، المسودات لا تُحتسب، إزالة EXIF، معادلتا الجودة والمشرف ونسبة «جزئي»، منع أوزان ≠ 100
  وأثر تغييرها (الجديد فقط + إعادة الاحتساب)، قواعد المستفيد ومسح QR حقيقي (فك ترميز صورة الرمز)، مصفوفة الصلاحيات والنطاق وCSRF وقفل الدخول،
  بيانات معروفة ← أرقام لوحة المؤشرات لكل فترة وفلتر، أحدث الجولات = 4 ومجاورة لمؤشرات المقاولين، لا QR في الشريط الجانبي،
  وألوان الفئة (المراقب أزرق والمشرف أحمر) في السجل وأحدث الجولات والملاحظات والرسم، والتصدير بملفات فعلية.

## النشر (الإنتاج)

> **للنشر التجريبي خطوة بخطوة (قاعدة Supabase سحابية + سيرفر Render المجاني): [DEPLOY.md](DEPLOY.md)** — ملف `render.yaml` جاهز في المستودع.

1. **Supabase**: أنشئ مشروعًا (مُدارًا أو مستضافًا ذاتيًا — انظر «إقامة البيانات» أدناه)، ثم:
   ```bash
   npx supabase link --project-ref <ref>
   npm run db:push                      # الترحيلات: الجداول، RLS، الدوال، الحاوية الخاصة، pg_cron
   ```
   - فعّل امتداد **pg_cron** في المشروع (الترحيل ينشئه ويجدول المهام).
   - في إعدادات Auth: عطّل التسجيل الذاتي (Sign-ups) — الحسابات تُنشأ فقط عبر seed/الأداة الإدارية.
2. **البيانات الأساسية** مرة واحدة من جهاز موثوق بمتغيرات الإنتاج: `npm run db:seed` (احفظ كلمات المرور المطبوعة فورًا وسلّمها عبر قناة آمنة).
3. **صورة Docker**:
   ```bash
   docker build -t jodex .
   docker run --env-file .env.production -p 3000:3000 jodex
   ```
   الصورة تتضمن Chromium لتوليد PDF وتعمل بمستخدم غير root. الأسرار تُمرَّر وقت التشغيل فقط.
   (`docker compose up --build` يشغّل نفس الصورة باستخدام `.env.production`.)
4. **HTTPS إلزامي** خلف وكيل عكسي/موازن تحميل يضبط `X-Forwarded-Proto` و`X-Forwarded-For`؛ اضبط `TRUSTED_PROXY_HOPS` على عدد الوكلاء.
   التطبيق يعيد توجيه http إلى https ويرسل HSTS وCSP بـ nonce وبقية رؤوس الأمان.
5. **نطاقان**: `APP_BASE_URL` للوحة الإدارة والموظفين، و`PUBLIC_APP_URL` لروابط التقييم العامة المطبوعة في رموز QR.
6. **النسخ الاحتياطي اليومي**: فعّل النسخ اليومي/PITR لقاعدة البيانات في Supabase، وانسخ حاوية التخزين `photos` يوميًا
   (مثلًا عبر واجهة S3 المتوافقة في Supabase Storage إلى حاوية خارجية) مع اختبار الاستعادة دوريًا.
7. **قائمة تحقق الأمان**: `DEMO_MODE=false`؛ لا تضبط `JODEX_ALLOW_TEST_CLOCK` أو `JODEX_ALLOW_INSECURE_HTTP` إطلاقًا؛
   `APP_SECRET` و`CRON_SECRET` عشوائيان وطويلان؛ مفتاح `service_role` في الخادم فقط.

### إقامة البيانات والاستضافة (قرار مفتوح)

النطاقات ومكان الاستضافة وإقامة البيانات داخل المملكة **لم تُحسم** وتحتاج قرارًا من الجهة. التطبيق يعمل مع أي Supabase متوافق:
مشروع Supabase مُدار في منطقة مقبولة تنظيميًا، أو **Supabase مستضاف ذاتيًا** على مزوّد سحابي داخل المملكة (نفس الترحيلات والإعدادات).

## البنية باختصار

```
app/                 الصفحات ونقاط الواجهة البرمجية (app/api/**) — كل نقطة تتحقق من الجلسة والدور والنطاق وCSRF
components/          واجهات المستفيد والمراقب والمشرف والأدمن (عربية RTL)
lib/domain/          قواعد العمل النقية (الخطة الزمنية والالتزام، الجودة، المشرف، المؤشرات، التحقق Zod)
lib/server/          منطق الخادم (المصادقة، الصلاحيات، الصور، التقارير، الاستعلامات)
supabase/migrations/ المخطط، RLS، الدوال الذرّية والمشغّلات، التخزين، pg_cron
scripts/             seed، الأداة الإدارية، تشغيل المهام المجدولة
tests/               unit · integration · e2e
```

- **الكتابة كلها عبر الخادم** بعد التحقق، وبدوال ذرّية في قاعدة البيانات تمنع الإرسال المكرر؛ لا توجد أي صلاحية كتابة مباشرة لأي دور.
- **القراءة** محكومة بـ RLS: المراقب دورته فقط (النائب دورة من ينوب عنه)، المشرف المواقع المسندة، الأدمن الكل، والزائر لا شيء.
- **الجولات والتقييمات المرسلة غير قابلة للتعديل أو الحذف** (مشغّلات قاعدة البيانات)، وتحفظ نسخة الأوزان المستخدمة.
- **سجل تدقيق** لكل دخول وإرسال وتعديل إعدادات واعتماد مكافأة وطباعة QR وتصدير.
